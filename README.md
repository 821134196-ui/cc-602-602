# 高校论文匿名送审与意见归档系统

学生论文送审前完成匿名检查，学生与导师查看进度或评阅意见时无法获知评阅人身份。

## 技术栈

- 后端：Rust + Axum + SQLx（SQLite），稿件存本地 `data/uploads/`
- 前端：Svelte + Vite（构建后由后端托管）
- 邮件：模拟接口（写入 `notifications` 表并打印日志，页面“通知”栏可见）

## 一键启动

```bash
./start.sh
```

脚本会安装前端依赖、构建前端，并启动后端：<http://localhost:3000>

（也可分步执行：`cd frontend && npm install && npm run build`，然后 `cargo run --release`。）

## 业务流程

1. **学生**创建论文并上传稿件（可多次上传，每次生成新版本）。
2. **导师**确认稿件可送审。
3. **秘书**做匿名内容检查，**冻结**确定的稿件版本作为送审稿，并**分配**给评阅人。
4. **评阅人**下载送审稿并提交评阅意见。
5. 全部评阅完成后，**秘书开放意见**，学生与导师才能看到（匿名）评阅结果。

学生页面会分别标注**最新上传稿**与**实际送审稿**；秘书页面展示每轮送审的版本与分配记录，后续上传不会被误认为已送审。

## 关键安全设计

- **版本冻结**：冻结记录（`freezes`）指向固定版本，学生送审后重传只新增版本，不替换评阅人收到的附件；是否以新版本重新送审由秘书决定（重新冻结 + 重新分配）。
- **匿名性**：学生/导师视角的 API 只返回“评阅人 1 / 2 / …”编号，不含评阅人 id、姓名、账号；评阅人视角只返回匿名编号 `T-xxxx`，不含学生/导师身份。
- **附件下载鉴权**：统一下载接口按角色校验——学生限本人论文、导师限指导学生、评阅人限被分配的那次冻结版本、秘书全部；未登录 401、越权 403、不存在 404，无法靠猜测版本号下载他人论文。
- **角色隔离**：评阅人名单等秘书接口仅秘书可访问；评阅人只能看到/评阅分配给自己的任务。

## 验证

```bash
cargo test
```

集成测试覆盖：

1. `anonymity_not_leaked_to_student_or_advisor` — 学生/导师响应中不含任何评阅人身份；意见开放前不可见；未收齐意见不能开放。
2. `reupload_preserves_frozen_review_version` — 送审后重传，评阅人仍下载到冻结时的 v1；v2 对评阅人不可见；秘书可冻结 v2 重新分配。
3. `unauthorized_download_rejected` — 其他学生/非指导教师/未分配评阅人下载被拒（403），未登录 401，猜测 id 404。
4. `role_and_assignment_scoping` — 角色接口隔离；评阅人仅见自己的任务且看不到师生身份；不能替他人任务提交意见。

```
│   ├── db.rs           # SQLite schema 与演示数据
│   ├── handlers/       # 学生/导师/秘书/评阅人/下载 接口

└── data/               # 运行时生成：thesis.db + uploads/
```
