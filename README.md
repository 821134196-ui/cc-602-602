# 高校论文匿名送审与意见归档系统

学生论文送审前完成匿名检查；学生与导师查看进度或评阅意见时无法得知评阅人身份。

## 技术栈

Rust + Axum（后端）· Svelte + Vite（前端）· SQLx + SQLite（数据库）· 本地文件存储 · 模拟邮件（落库 + 日志）

## 一键启动

```bash
./start.sh
```

首次运行会安装前端依赖、构建前端并启动后端，访问 http://localhost:3000 。
数据保存在 `./data/`（`app.db` 与 `uploads/`），删除该目录即可重置。

## 业务流程

1. **学生**上传稿件（可多次上传，每次生成新版本）。
2. **导师**确认当前版本可以送审。
3. **秘书**进行匿名检查（系统提供敏感词扫描辅助）：通过后**冻结该版本**创建送审轮次；不通过则退回，学生修改后重新上传、导师重新确认。
4. **秘书**为冻结稿分配评阅人（系统生成“评阅人甲/乙…”匿名别名，并发送模拟邮件通知）。
5. **评阅人**下载冻结稿并提交评阅意见；全部提交后轮次自动完成。
6. **秘书**归档并向学生开放意见。

关键规则：

- 学生页面分别展示**最新上传稿**与**实际送审稿（已冻结）**；秘书页面可查看送审版本与全部分配记录。
- 送审期间学生重传稿件**不会替换**评阅人收到的附件；是否以新稿重新送审由秘书决定（重新送审会作废旧轮次，评阅人对旧稿的下载权限随即回收）。
- 学生与导师只能看到匿名别名与意见内容，API 响应中不包含任何评阅人身份信息。
- 评阅人只能看到分配给自己的稿件，且看不到学生身份。
- 附件下载按角色逐一鉴权：学生/导师限本人论文，评阅人限所分配轮次的冻结版本，无法通过猜测地址越权下载。

## 验证

```bash
cd server && cargo test
```

集成测试覆盖：

- `anonymity_not_leaked_to_student_or_advisor` — 学生/导师/评阅人各视角的响应中不含对方身份信息；越权接口返回 403。
- `reupload_keeps_frozen_review_version` — 送审中重传后，评阅人下载到的仍是原冻结稿；新稿对评阅人不可见；重新送审后旧稿权限被回收。
- `unauthorized_downloads_are_rejected` — 未登录 401、他人论文/未分配评阅人/无关导师下载 403、不存在版本 404、越权提交意见 403。

## 开发模式

```bash
cd server && cargo run          # 后端 :3000
cd web && npm run dev           # 前端 :5173（/api 代理到 3000）
```

环境变量：`PORT`（默认 3000）、`DATA_DIR`（默认 ./data）、`WEB_DIST`（默认 ./web/dist）。
